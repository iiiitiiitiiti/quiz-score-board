## 001. ルールは純関数にし、履歴は変わった値の前後で持つ

- 日付: 2026-10-20
- 対象: `src/rules/`・`src/store/reducer.js`・`src/store/persistence.js`

### 決定

得点制・○×制の2モードを、9ルールから選ぶ方式に置き換えた。各ルールは「○✕が押されたら全員の状態をどう変えるか」を返す純関数で、reducer は `answer/record` 1つでそれを呼ぶ。undo・redo は変わった人の前後の値を書き戻す。比較の全体は `docs/plan-rules.md`「案の比較」が正本。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| ルールごとに reducer のアクションを分ける | undo・redo・sanitize の4箇所がルールの数だけ増え、足すたびに漏れやすい |
| 履歴を最初から再生して今の点数を出す | 履歴は保存時に直近500件へ切り詰めるため、古い分を再生できない |
| 勝ち抜けの番号を「済んだ人数+1」だけで出す | 済んだ人を削除すると次の人と番号が重なる。人数と付いている最大の番号の大きい方+1にした |

### 影響範囲

- 元に戻せる操作を足すときも `answer/record` の changes に乗せる（CLAUDE.md の undo の注意書き）
- 旧形式の履歴（`score/update`・`circle/record`）は読み込み時に変換する
- 後半の問題の数を使うルール（`docs/plan-rules.md` 後半）はこの仕組みの上に足す

### 検証

`npm test`（ルール・reducer・保存の38件）と、dev サーバーで9ルールを1回ずつ操作して確かめた。複数人を同時に変えるルール（通過クイズの阻止・サバイバル・ザー）の undo で値がずれたら、この判断を見直す。
